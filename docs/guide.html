The Orim guide

Task-by-task how-tos for everything Orim does. Orim treats a board as a structured document, so most features connect: the diagram you import can be authored by keyboard, summed by a frame, fed by a spreadsheet, read by a screen reader and edited by an agent.

Boards & projects

Create a board

  1. On the start page, click New board and name it — or click a template card (Retrospective, Kanban, Flowchart, Sprint table, Org chart, Mind map, SWOT, Service blueprint) to start pre-built.
  2. A board's URL is its identity: /?b=my-board. Sending the URL is sharing it (see Sharing).

Organise boards into projects

Hover a board card and click Move…, then type a project name. The start page groups boards into project sections; boards without a project sit under Unfiled. Moving is owner-only once a board has been claimed.

Duplicate, rename, delete

All on the board card's hover actions. Duplicate copies the whole board server-side into the same project (the copy starts unclaimed, in link-edit mode). Deleting a board also deletes its history and cannot be undone.

Boards are local-first: every board you open is kept in your browser (IndexedDB) and works offline; the server syncs and persists. If the server is unreachable, the start page lists the boards you've opened on this device.

Canvas basics

Tools

The left toolbar (or its keys): select V, pan H, sticky N, rectangle R, ellipse O, diamond D, text T, frame F, connector C, pen P, table G, comment M. Click the canvas with a creation tool to place the object; text editing opens immediately where it makes sense.

Moving around

Scroll to pan, pinch or ⌘-scroll to zoom, 1 zooms to fit, 0 resets to 100%. The minimap (bottom right) shows where you are; drag it to jump.

Selecting & editing

  • Click selects; drag empty canvas for a marquee; Shift-click adds to the selection; ⌘A selects all.
  • Drag corners to resize. Double-click a sticky, shape or text to edit its text (a real rich-text editor); Esc commits.
  • Arrow keys nudge the selection 8px; Shift+arrows 32px. Frames carry their contents; locked objects stay put.
  • ⌘C/⌘V copy and paste — including into a different board or tab: the copy travels through your system clipboard, and bindings, frame contents and connector anchors all survive. ⌘D duplicates in place, ⌘] brings to front, ⌘Z/⇧⌘Z undo and redo.
  • The swatch at the bottom of the toolbar opens the color and fill popover; it also switches a selected shape's kind (sticky ↔ rect/ellipse/diamond/pill) in place — text, data and bindings survive the conversion.

Frames

Frames group content spatially: anything placed inside belongs to the frame, moves with it, and defines the board's reading order — which drives exports, the accessibility tree and present mode. Double-click the title strip to rename.

Connectors

Draw one

  1. Hover any node — four round ports appear on its edges.
  2. Drag from a port to another node (or use the connector tool C and drag between objects).

Connectors are FigJam-style elbows with rounded joins that route around obstacles automatically and re-route live as you move things. Double-click a connector to give it a label.

Connect to a table row — or bind to a cell

  • Drop the connector on a table's header or edge for an ordinary arrow to the table.
  • Drop it on a row and the arrow anchors to that specific row, following it as the table moves.
  • Drop it from a sticky onto a specific cell (the cell highlights while you hover) and instead of an arrow you create a cell binding — see cell-bound stickies.

Org charts & trees

Any strictly hierarchical diagram — org charts, mind maps, outlines — gets first-class treatment. Trees imported from CSV, or started by hand, keep themselves tidy.

Author with the keyboard

  • Select any node and press Tab: a connected child appears, inherits its siblings' look, opens ready to type — and the whole tree rebalances (children grouped under parents, every parent centered over its subtree).
  • Enter adds a sibling. Tab on a lone sticky starts a brand-new tree.
  • A selected tree node shows a + button beneath it — clicking it is the mouse version of Tab.
  • Arrow keys walk the structure: up to the parent, down to the nearest child, left/right between siblings. Alt+arrows move the node instead.
Drop samples/team.csv (a Name/Role/Manager sheet) on the canvas and you get a balanced org chart instantly — then Tab your way to the new hires.

Import: files & paste

Drop a spreadsheet, get the right diagram

Drag a CSV, TSV or Excel file onto the canvas. Orim inspects the data's shape and builds:

  • a column referencing another column's values → an org chart
  • from/to columns → a dependency graph
  • a low-cardinality status column → kanban lanes
  • anything else → a table

Every generated object carries its source row in its data bag, so the diagram is still a database.

Paste almost anything

  • Mermaid flowcharts become live, routed diagrams.
  • Markdown outlines become framed sticky sections.
  • Spreadsheet cells (TSV from Excel/Sheets) run the same inference as file drops.
  • Plain text becomes stickies, one per line.
  • A URL becomes a live embed; an image becomes an image node (see below).
  • An Orim board file (a JSON export, or the Miro importer's output) drops back in whole — objects land at their authored positions with fresh ids, frames, bindings and connectors intact.

Migrate from Miro

  1. Get a Miro access token with boards:read (Miro → profile settings → Your apps).
  2. Run the importer against your board id: 
    export MIRO_TOKEN=...
cd packages/convert
node --import tsx scripts/import-miro.mjs <miro-board-id>
  3. Drop the resulting .orim.json onto any Orim board.

Sticky notes, shapes, text, frames (with membership), cards, embeds and connectors map across — colors to the nearest palette, HTML to plain text, positions converted exactly. Images inline when Miro exposes their bytes (placeholders otherwise), and anything unmappable is counted and reported, never silently dropped.

Images & live embeds

Images

Drop an image file or paste a screenshot. Images are stored inside the document (downscaled to stay portable — max 1600px edge), so boards remain one self-contained file: no blob store, works air-gapped, and images survive export to SVG.

Live website embeds

  1. Drop a link (from the address bar, a bookmark) or paste a URL.
  2. A resizable frame shows the live site. Move and resize it like any object — clicks pass through to the board.
  3. Double-click the embed to interact: scroll the page, click its links. Esc or clicking the board hands the pointer back.
Sites that forbid framing (banks, most Google apps) show an empty card — the hostname chip above it still says what it is. Embeds are sandboxed with least privilege and send no referrer.

Tables

  • Create with the table tool G. Double-click any cell to edit; Tab moves through cells; double-click a header to rename the column.
  • Add rows and columns from the data panel's table actions (\ with the table selected).
  • Numeric columns grow a totals footer automatically, and the board's currency setting formats cost-like columns (see smart fields).

Cell-bound stickies

A sticky can be a live view of one table cell. The cell is the source of truth; the sticky's position is entirely its own — layout is independent of data.

Create a binding

  • From the canvas: drag a connector from a sticky onto the exact cell (it highlights). An empty cell first adopts the sticky's text, so linking never loses work; a filled cell wins.
  • From the table: select it, open the data panel and use Rows → stickies to materialise a bound sticky per row.

How bindings behave

  • Edit the cell → the sticky updates. Edit the sticky → the cell updates. Everyone sees both, live.
  • Select a bound sticky (or its table) and an animated dashed link shows the relationship — it's a data link, not a drawn line, and it never exports.
  • Bindings survive copy/paste (copy table + stickies together and the copies bind to the copied table) and linked-table refreshes.

Cluster synthesis

The reverse trick: turn a wall of stickies into structured data.

  1. Select a pile of stickies (marquee or ⌘A).
  2. In the data panel, choose Synthesize table.
  3. Orim detects the spatial clusters (frame titles become cluster names), builds a table with one row per sticky — and binds every sticky to its row, closing the loop: cell edits flow back to the wall.

Smart fields

Put numbers on stickies

  1. Select a sticky, open the data panel (\) and add a field: estimate: 5, cost: 1200.
  2. Numeric fields render as chips on the sticky. Double-click a chip to edit the value in place.

Zero-config aggregates

Put stickies with a shared numeric field inside a frame and the frame grows an aggregate chip — no setup. Click the chip to cycle Σ sum → average → min → max → count. Sprint capacity, budget workshops and RICE scoring fall out for free.

Conditional colors

Spreadsheet-style formatting for the canvas: in the data panel, add rules like Cost > 200000 → red or status contains blocked → orange. Rules are evaluated live at render time — first match wins, the note's own color is never overwritten, and edits that cross a threshold recolor instantly. Rules sync with the board, so everyone sees the same signals.

Currency

Cost-shaped fields format with your currency. Set it once per board at the top of the data panel (auto picks from your locale).

Agents can write fields over MCP — "estimate these 20 stickies" — and the chips, aggregates and exports update live.

Linked tables

Feed a table from a CSV URL — a published Google Sheet, an internal BI export, any endpoint your server's operator has allow-listed.

Set up

  1. Operator, once: set ORIM_FETCH_ALLOW on the server to the hosts tables may fetch from (e.g. docs.google.com,data.internal.example). Unset, the feature is off and the server makes no outbound calls.
  2. In Google Sheets: File → Share → Publish to web → CSV, and copy the URL. (Any plain CSV/TSV endpoint works the same.)
  3. In Orim: select the table, open the data panel, click Link to URL… and paste it.

Refreshing

  • Click Refresh from <host> anytime; boards also refresh stale feeds (>5 minutes) when opened.
  • The source is one-directional truth: refresh replaces columns and rows — but matches columns by header name and rows by first-column key, so bound stickies, aggregate settings and totals survive.
  • Every fetch is audited server-side; responses cap at 2 MB.

The data panel

\ (or the board menu → Data) opens the panel: the board as data rather than pixels.

  • Outline — every object in reading order; click to select and jump the camera.
  • Inspector — the selected object's type, geometry, bindings and typed fields, with add/remove rows and an Edit as JSON escape hatch.
  • Table actions — rows/columns, rows → stickies, linked sources, synthesis.
  • Code view — flip the Data/Code toggle to see the selection (or the whole board) as live JSON, updating as the board changes — the document behind the canvas, one Copy click away.

Sharing & roles

Share a board

Board menu → Share. Pick a mode:

  • Anyone with the link can edit (default for new boards)
  • Anyone with the link can view — viewers' connections are read-only at the sync server, not just in the UI
  • Private — only people you name connect at all

Grant specific people editor or viewer by account name. The first time you restrict a board you become its owner; share settings, rename, move and delete are owner-only from then on.

Signing in

Password accounts, or single sign-on through your organisation's identity provider when the server has OIDC configured (the sign-in dialog shows the SSO button automatically).

Local-first honesty: someone whose access is revoked keeps the copy their browser already synced — clearly labelled read-only — but receives nothing new, like a revoked file share.

Comments

  • Comment tool M, then click an object (the thread follows it) or empty canvas (it stays at that spot).
  • Pins show on the board; click one to read, reply or resolve. Unresolved comments are announced to screen readers and appear in the accessibility tree.

Workshops

Dot voting

  1. Board menu → Vote: set a budget per person (e.g. 5 dots) and optionally a timer.
  2. Everyone clicks stickies to spend dots — live badges show totals, and simultaneous votes can't clobber each other (each vote is its own CRDT entry).
  3. Finish with Rank into table: one click builds a results table, ordered by votes, with every sticky bound to its row.

Shared timer

Board menu → Timer. Everyone sees the same countdown; a gentle chime marks zero.

Private drafts

  1. Board menu → Drafts: write ideas only you can see (they live on your device until revealed).
  2. Reveal puts your drafts on the board — or the facilitator hits Everyone reveal and all drafts land simultaneously. Nobody anchors on the loudest voice.

Present mode

  1. Put your content in frames — each frame is a slide, in the board's reading order.
  2. Board menu → Present. The camera glides to slide one and the UI gets out of the way.
  3. →/Space and ← move between slides; Esc exits.

The board stays live while you present — collaborators' edits appear on the slide — and every slide change is announced to screen readers. Viewers can present too.

Board history

  • Board menu → History. Versions are captured automatically as the board changes; Save labelled version… marks a moment you care about ("pre-workshop baseline") — labelled versions are never pruned.
  • Click a version to time-travel: the canvas shows that state, read-only. Esc or Back to now returns.
  • Restore this version rolls the board back — applied as an ordinary edit, so it syncs to everyone, lands in the audit log with your name, and ⌘Z undoes it.

Exports

Board menu → Export:

  • Markdown — the board in reading order: frames as sections, real Markdown tables, field values, vote counts, connection lists. Paste it back into a board and it rebuilds.
  • Mermaid — connected diagrams as diagram-as-code (also round-trips via paste).
  • SVG / PNG — vector and raster snapshots (images embed).
  • JSON — the full open format, validated by a published JSON Schema generated from the source of truth. See the format spec.

Accessibility

Every board is mirrored as a native ARIA tree in reading order — the same order exports use, so what a screen reader hears is what the Markdown says.

  • Tab into the board contents tree: arrows navigate, frames and tables expand, Enter edits text in place, Delete removes. Selection follows focus and the camera follows selection.
  • Rich labels: "Sticky note: Open file format, green, 3 votes, estimate 5"; connectors described in prose; frames announce their aggregates.
  • Additions, removals and edits — including collaborators' and agents' — are announced via a polite live region.
  • On the canvas itself, diagrams can be read, authored and arranged without a pointer: arrow navigation, Tab/Enter authoring, arrow-key nudge.

Agents (MCP)

Orim ships an MCP server, so an LLM agent is a first-class collaborator — its edits ride the same CRDT pipeline as everyone else's, appearing live on the board.

{
  "mcpServers": {
    "orim": {
      "command": "node",
      "args": ["--import", "tsx", "apps/mcp/src/server.ts"]
    }
  }
}

Tools: list_boards, read_board (markdown/json/mermaid/svg), create_objects (with $n cross-references and overlap warnings), update_objects, delete_objects, apply_layout, find_empty_space, synthesize_table.

Agent connections are guests by default; set ORIM_TOKEN to a session token to act as a user under your board roles and audit trail.

Admin console

The first account created on a server is its admin. Visit /admin (an Admin button appears on the start page) for:

  • Overview — users, boards, active sessions, audit volume.
  • Users — promote/demote admins, sign a user out everywhere, remove accounts (their boards survive unclaimed). Guardrails are server-enforced: never zero admins, no self-delete.
  • Audit log — filterable by user, action and board, with paging; every sign-in, connection, share change, restore and admin action. Deployment, hardening and SIEM notes: SECURITY.md and DEPLOY.md.
